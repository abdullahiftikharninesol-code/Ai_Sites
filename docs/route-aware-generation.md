# Route-aware functional generation release gate

Run `npm run test:route-aware-generation`, `npx tsc --noEmit`, and `npm run build:server` before releasing changes to functional generation. The suite uses deterministic mock provider responses, local execution, real production builds and Chromium, in-memory project/job/billing doubles, and local artifacts. It requires cached starter dependencies and installed Playwright Chromium. No API keys, live providers, MongoDB, Redis or GCS are required. Starter installation runs with npm offline enabled in the pipeline fixtures. One synthetic credit in the billing double is an assertion, not a real account charge.

For the focused accordion/evidence gate, run `npm run test:accordion-reliability`. Static evidence is three-state: `RECOGNIZED` means a rendered structural candidate still requiring behavior validation; `PROVEN_MISSING` requires a closed render graph with no possible control; `UNCERTAIN` covers custom/dynamic/opaque implementations. Comments, visible copy, component names and unused imports cannot establish capability presence. Unknown implementations remain mandatory and proceed to Browser QA. Requested functional requirements force behavior QA even if optional QA was disabled. This changes no provider roles, call limits or repair allowances.

Accordion verification supports native details, ARIA-associated panels, custom React conditional answers, nested headings and flat question/answer siblings. It tests local visible answer text appearing/disappearing and state consistency, including initially open controls. Menus, cosmetic label/class/ARIA changes, unrelated notifications, empty answers, hidden controls, wrong panel references and answers that never close must fail. The regression includes the retained `af251cf0` failure shape and short/long equivalent requirements; mocked output is not a live-provider guarantee.

The retained website also exposed native-control assumptions covered by this gate: wrapping `<label>` associations are valid without `for`/`id`; required select/checkbox controls must be completed before probing a demo submission; a mobile disclosure may reveal an unambiguous semantic navigation without `aria-controls` (a supplied relation must still be valid); result identity must survive changing ordinal badges after filtering. Project cards can be articles or heading-bearing interactive cards. Real invalid submissions, remote writes, empty choices, missing labels, inert filters, broken panel references and menus that never close retain their existing failure policy.

The gate must fail when a valid route-scoped feature is rejected, a missing/broken feature passes, exact-template loading regresses, or atomic persistence/billing safety regresses. Browser test timeouts in CI allow the existing production checks to finish; production QA deadlines, error severity and inference budgets remain unchanged.

## Contract and completion

Deterministic extraction preserves explicit page declarations and the page blocks owning each requested capability. Global reminders do not inherit the last page. Each mandatory requirement has a stable ID, capability, page/section/site scope, expected behavior and browser validation method. The same compact ownership guidance reaches an optional existing Planner and the existing Site Coder through SiteSpec. There are no new model roles or calls.

Section mentions do not override page ownership. Placement must directly qualify the interaction in the same affirmative clause; other pages, neighboring content and negative instructions cannot invent section constraints. Unquoted descriptions such as “portfolio section” remain location hints, without requiring a literal heading or ID. Explicit IDs (`in #project-inquiry`, `inside the section with id="project-inquiry"`) remain strict. Explicitly named/quoted section labels resolve against actual accessible labels or headings, independently of generated IDs; missing, hidden or ambiguous matching sections fail. Dynamic JSX IDs are checked in the browser when static source cannot prove their identity. The live Contact regression is covered by varied prompt fixtures and the real five-page pipeline; actual forms remain mandatory.

Completion resolves actual source routes and rendered component graphs, including pathname conditionals/switches, React Router JSX, used router object configurations, and static route dictionaries. Imports and nested page components contribute source references. Portfolio labels such as Our Work, Projects and Case Studies can bind to `/work`, `/our-work`, `/portfolio`, `/projects` or other actual slugs; aliases alone never fabricate routes. Unused components, unused route metadata, incidental headings and text mentioning categories do not prove a page or feature.

Provably missing routes/controls fail before building. Unknown component wiring is deferred to browser behavior rather than rejected solely for a component name. Arbitrary dynamic routing, computed route factories, re-export chains and unusual navigation structures may remain ambiguous and are safely rejected with a diagnostic; they are not silently accepted. No generated functionality is invented by this mapping layer.

## Behavior and adversarial fixtures

The realistic five-page fixture places hero/FAQ on Home, service tabs on Services, filters/detail modals on Our Work, company content on About and the validated local form on Contact. Home deliberately has no category filter. The actual deterministic planners, completion/static validators, compiler, production build, all three viewport QA checks, current-source persistence and reload are exercised.

Filtering supports semantic selects, buttons and tabs. Results must become a nonempty strict subset, selection must be observable, and All must restore the original collection. Text-only category labels, no-op callbacks, cosmetic state alone and filters hidden in another section cannot satisfy the requirement. Tabs must switch and restore meaningful panels; accordions and modals must open meaningful content and close. Forms reject invalid email and require honest local feedback without a network submission. Required pages must be reachable through real navigation, including collapsed mobile navigation.

Fixtures A/B cover a valid multi-page site with the filter only on `/work`; C a missing filter; D a decorative filter; E an unused/missing portfolio route; F alternate slugs and control implementations; G an unrequested filter; H mobile navigation, filtering and direct reload; I failure evidence/no accepted current source/no successful billing; J existing exact-template/Targeted Edit regressions. Existing functional fixtures and template tests cover SaaS, ecommerce, restaurant, corporate and personal portfolio behavior. Source-contract tests cover JSX React Router, nested object routes, static route dictionaries and switches. Section-scoped browser tests reject unrelated working controls outside the required section.

## Diagnostics and operating boundaries

Private failed-candidate diagnostics now include bounded route mappings, requirement IDs/types, expected and actual probe routes, results, source file/line references, model/role and physical/logical counts. Existing storage limits remain five files, two MiB per file, 24 hours, secret filtering and disabled production retention. Source content remains private; public development telemetry uses a metadata whitelist. Total QA timeout produces a blocking partial report identifying unvalidated routes, allowing the normal failure diagnostic path to retain evidence instead of misclassifying the exception as static validation.

Terminal development telemetry includes outcome, request counts and actual billing status. `summarizeGenerationReliability` aggregates existing events by unique job ID into completion rate, failure stage/category counts, physical requests and successful billing outcomes. It is read-only and never triggers inference or shared writes. Production operational aggregates can use the existing persisted job/accounting records; development retention is not an audit ledger.

The exact-template workflow, Targeted Edit scope/patch safety, Build Repair snapshot checks, current-version-only persistence and billing formulas are unchanged. Services need a normal rebuild/restart to load changes; the offline suite does not start the Sites API or GetChatly frontend.

Mocked model output proves deterministic pipeline behavior and catches false acceptance/rejection. It does not prove that a live model will always produce complete, compilable or functional source. Invalid live output must still fail safely. A separately authorized manual live generation remains necessary to evaluate provider output quality; this gate contains no continuous paid testing or hidden retries.
